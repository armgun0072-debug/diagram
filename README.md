# Schema Studio

เว็บออกแบบ ER Diagram สำหรับรันบน Windows เครื่องตัวเอง สร้างด้วย **React + TypeScript + Vite + React Flow + ELK.js** และใช้ CodeMirror เป็น Code Editor

มีแท็บ **ER Diagram / Flowchart** สำหรับออกแบบฐานข้อมูลและขั้นตอนธุรกิจที่อ้างอิงตาราง/คอลัมน์ชุดเดียวกัน

โปรเจกต์นี้เป็นโค้ดเริ่มต้นที่ใช้งานได้จริง โดยได้แนวคิดจากการออกแบบ Diagram ด้วยโค้ดของ dbdiagram.io ไม่ใช่สำเนาผลิตภัณฑ์ทั้งหมด

## สำหรับคนหรือ AI ที่รับงานต่อ

เริ่มจาก [AGENTS.md — กติกาการทำงานและการรอ approve](AGENTS.md) แล้วอ่าน [HANDOFF.md — สถานะล่าสุดและแผนที่ไฟล์](HANDOFF.md) เพื่อเลือกเปิดโค้ดเฉพาะส่วนที่เกี่ยวข้อง ส่วน [CHANGELOG.md — ประวัติสิ่งที่ทำแล้วและผลตรวจ](CHANGELOG.md) ใช้ดูเหตุผลและงานที่ผ่านมา หลังทำงานให้ปรับเอกสารเหล่านี้ตามกติกาใน AGENTS

หากส่งโฟลเดอร์โปรเจกต์ให้ผู้อื่น ข้อมูล Diagram ในเบราว์เซอร์จะไม่ติดไปด้วย ให้ดาวน์โหลด `.erd.json` จากแอปแล้วส่งแนบ ดูรายละเอียดการส่งต่อใน HANDOFF

## ติดตั้งบน Windows

1. ติดตั้ง **Node.js รุ่น 22 LTS ตั้งแต่ 22.12 ขึ้นไป** จาก https://nodejs.org/ (Node.js รุ่นใหม่กว่าก็ใช้ได้) แล้วปิดและเปิด Terminal ใหม่
2. เปิด PowerShell หรือ Terminal ใน VS Code แล้วเข้าโฟลเดอร์โปรเจกต์:

   ```powershell
   cd D:\daigramweb
   node --version
   npm.cmd --version
   npm.cmd ci
   npm.cmd run dev
   ```

3. เปิด URL ที่ Vite แสดง เช่น **http://127.0.0.1:5173** ใน Edge หรือ Chrome หากพอร์ตถูกใช้ Vite จะเลือกพอร์ตถัดไป
4. หยุดเซิร์ฟเวอร์ด้วย **Ctrl+C**

ใช้ `npm.cmd` เพื่อหลีกเลี่ยงปัญหา PowerShell บล็อก `npm.ps1` โดยไม่ต้องเปลี่ยน Execution Policy หากใช้ Command Prompt สามารถพิมพ์ `npm` แทน `npm.cmd` ได้

โค้ดและ `package-lock.json` พร้อมใช้งานแล้ว ไม่ต้องรัน `npm create vite` ซ้ำ การติดตั้งแพ็กเกจครั้งแรกต้องใช้อินเทอร์เน็ต หลังติดตั้งแล้วแอปทำงานในเครื่อง ไม่มี backend หรือฐานข้อมูลให้ตั้งค่า ไม่มีการเรียก CDN หรือโหลดฟอนต์จากภายนอกขณะใช้งาน

## วิธีใช้งาน

- **Code Editor**: แก้โค้ดในแผงซ้าย Diagram เปลี่ยนทันทีเมื่อโค้ดถูกต้อง ถ้าเขียนไม่ครบหรือผิดไวยากรณ์จะแสดงข้อผิดพลาดพร้อมเก็บ Diagram ล่าสุดที่ถูกต้องไว้
- **Visual Designer**: กดเพิ่มตาราง คลิกเลือกตารางแล้วกดแก้ไข หรือดับเบิลคลิกตาราง ใส่ชื่อตาราง ชื่อคอลัมน์ ชนิดข้อมูล และ flags จากนั้นกดบันทึก
- **ย้ายตาราง**: ลากส่วนหัวที่เป็นชื่อตาราง ตำแหน่งจะคงอยู่เมื่อสลับโหมด
- **การลากที่ลื่นขึ้น**: ระหว่างลากใช้เส้นตัวอย่างแบบเบาที่ตามคอลัมน์ทันที เมื่อปล่อยจึงคำนวณเส้นหลบตารางละเอียดผ่าน Web Worker และบันทึกตำแหน่ง อาจเห็นเส้นยังจัดทางไม่เสร็จสั้น ๆ ระหว่างลาก/รอผล ตัวแอปไม่สะสมงานคำนวณของตำแหน่งเก่า
- **เส้นตามตารางและหลบสิ่งกีดขวาง**: เส้นจะขยับตามคอลัมน์และเลือกจุดเชื่อมซ้าย/ขวาใหม่ระหว่างลาก โดยหาเส้นทางหักมุมผ่านช่องว่างรอบตารางและเว้นระยะจากกรอบ มีการจองช่องทางเพื่อลดช่วงที่เส้นซ้อนทับกัน รูปแบบจัดตำแหน่งเว้นช่องว่างเพิ่มสำหรับการเดินเส้น
- **อ่านความสัมพันธ์**: ป้าย `1` / `N` อยู่ใกล้ปลายเส้นทั้งสองฝั่งตลอดเวลา เช่น `customers [1] ─── [N] orders` โดยป้ายผูกกับตารางแม้ลากสลับฝั่ง รองรับ `1:1`, `N:N` และ optional (`0..1` / `0..N`) เมื่อชี้หรือเลือกเส้นจะแสดงป้ายรวมกลางเส้นเพิ่มเติม เส้นที่ชี้เปลี่ยนเป็นสีเขียวพร้อมเส้นประวิ่ง และหยุดเมื่อเลื่อนเมาส์ออก ชื่อคอลัมน์ต้นทาง/ปลายทางอยู่ใน tooltip
- **เปลี่ยนสีหัวตาราง**: คลิกไอคอนจานสีบนหัวตาราง หรือคลิกเลือกตาราง แล้วเลือกสีจากแผงมุมขวา มีสีสำเร็จรูปและปุ่มเลือกสีเอง พื้นหลังหัวตารางจะเปลี่ยนเป็นสีที่เลือกเต็มพื้นที่ พร้อมปรับสีตัวหนังสือให้เหมาะกับพื้นหลัง ใช้ได้ทั้ง Code Editor และ Visual Designer กดลูกศรวนเพื่อคืนสีเริ่มต้น สีบันทึกในเบราว์เซอร์และไฟล์โปรเจกต์ `.erd.json` (ไฟล์ `.dbml` เก็บเฉพาะโครงสร้าง)
- **เชื่อมคอลัมน์**: ในโหมด Visual ลากจุดด้านขวาของ Foreign key ไปยังจุดด้านซ้ายของคอลัมน์ที่อ้างอิง จะสร้างเส้น N : 1 และเพิ่ม `Ref` ในโค้ด
- **ลบเส้น**: ในโหมด Visual คลิกเส้นแล้วกดไอคอนถังขยะในแถบที่ปรากฏ
- **ลบตาราง**: เลือกตารางในโหมด Visual แล้วกดลบตาราง ความสัมพันธ์ที่อ้างถึงจะถูกลบด้วย
- **จัดตำแหน่ง**: กดปุ่มจัดตำแหน่งเพื่อเปิดเมนูเลือก Left-right, Pipeline, Snowflake, Compact หรือ Flowchart ซ้าย → ขวา แล้วแอปจะจัดวางและปรับมุมมองให้เห็นตารางทั้งหมด รูปแบบที่เลือกเก็บไว้ในเบราว์เซอร์และไฟล์ JSON ใช้ปุ่มลูกศรเพื่อเลือกเมนู หรือกด 1–5 ขณะที่เมนูเปิดอยู่ได้ React Flow เป็นผู้วาดเส้นระหว่างคอลัมน์
- **บันทึก**: แอปบันทึกโค้ดและตำแหน่งใน `localStorage` โดยอัตโนมัติ กดบันทึกโปรเจกต์เพื่อดาวน์โหลด `.erd.json` เป็นไฟล์สำรอง เปิดกลับได้ด้วยปุ่มเปิดไฟล์
- **หลายโปรเจกต์ (Multi-project)**: กดที่ชื่อโปรเจกต์บนแถบ Header เพื่อเปิดเมนูสลับโปรเจกต์ สร้างโปรเจกต์ใหม่ (โปรเจกต์ว่าง หรือสร้างจากตัวอย่าง) เปลี่ยนชื่อ ทำสำเนา หรือลบโปรเจกต์ ทุกโปรเจกต์บันทึกแยกกันในเบราว์เซอร์นี้
- **แชร์ลิงก์ (Share Link)**: กดปุ่ม "แชร์ลิงก์" บนแถบเครื่องมือ ระบบจะบีบอัดข้อมูลแบบกระชับ และย่อเป็นลิงก์สั้นผ่าน Netlify Function (`/.netlify/functions/shorten`) ให้ทันที สะดวกต่อการส่งในแชท หากอยู่ออฟไลน์จะสลับไปใช้ลิงก์ตรง ผู้รับจะได้รับสำเนาไปเป็นโปรเจกต์ใหม่ในเครื่องของตนเองทันทีโดยไม่ต้องมีระบบล็อกอิน
- **นำเข้า/ส่งออกโค้ด**: ดาวน์โหลด `.dbml` จากด้านล่าง Code Editor และนำเข้า `.dbml` หรือ `.txt` ด้วยเปิดไฟล์ (รองรับเฉพาะไวยากรณ์ด้านล่าง) นำเข้าทีละไฟล์ ขนาดไม่เกิน 2 MB

การเปิดไฟล์จะเปลี่ยนงานปัจจุบัน ให้ดาวน์โหลดโปรเจกต์เดิมก่อนหากต้องการเก็บไว้ ไม่มีระบบ Undo ในรุ่นเริ่มต้นนี้ การแก้โครงสร้างด้วย Visual จะสร้างโค้ดใหม่ตามรูปแบบมาตรฐานและนำคอมเมนต์ออก

| รูปแบบจัดตำแหน่ง | การใช้งาน |
| --- | --- |
| Left-right | ใช้ ELK.js layered layout เรียงตาม Foreign key จากซ้ายไปขวา เหมาะกับความสัมพันธ์หลายขั้น |
| Pipeline | แบ่งขั้นตามการพึ่งพาข้อมูล และซ้อนตารางแต่ละขั้นในแนวตั้ง ตารางที่อ้างอิงวนกันจะอยู่ขั้นเดียวกัน |
| Snowflake | ตารางที่เชื่อมกับตารางอื่นมากที่สุดอยู่ตรงกลาง ตารางที่เกี่ยวข้องกระจายเป็นวงตามระยะห่างในกราฟ |
| Compact | วางตารางสูงก่อนลงในคอลัมน์ที่สั้นที่สุด เพื่อให้กลุ่มตารางเป็นสี่เหลี่ยมกระชับ |
| Flowchart ซ้าย → ขวา | วางตารางหลักที่ถูกอ้างอิงไว้ซ้าย แล้วแตกแขนงตารางลูกไปขวาตาม FK จัดลำดับตารางลูกตามแนวตารางแม่เพื่อลดเส้นไขว้ ตารางที่อ้างอิงวนกันอยู่ขั้นเดียวกัน และเก็บตารางที่ไม่เชื่อมกับใครไว้ด้วย |

ทั้ง 5 แบบคำนวณจากขนาดตารางเพื่อเว้นระยะไม่ให้ตารางซ้อนกัน Pipeline, Snowflake, Compact และ Flowchart เป็นอัลกอริทึมภายในแอป ส่วน Left-right ใช้ ELK.js การจัดตำแหน่งจะเปลี่ยนเฉพาะตำแหน่งและรูปแบบที่เลือก ไม่แก้โครงสร้างหรือสีตาราง โหมด Flowchart ของ ER อิง FK จึงไม่ได้อนุมานลำดับงานธุรกิจ; แท็บ Business Flowchart ใช้กำหนดขั้นตอนธุรกิจเอง

การเดินเส้นใช้ A* บนช่องทางแนวนอน/แนวตั้งรอบตาราง โดยคิดต้นทุนเพิ่มเมื่อเส้นต้องหักมุม ทับทางเดิม หรือตัดเส้นอื่น กราฟที่มีความสัมพันธ์มากยังอาจมีจุดตัดได้ ที่จุดตัดจะมีช่องว่างช่วยแยกเส้น และเมื่อชี้เมาส์เส้นนั้นจะขึ้นด้านหน้า เส้นที่อ้างคอลัมน์เดียวกันอาจใช้ช่วงสั้นใกล้จุดเชื่อมร่วมกัน หากลากกรอบตารางมาซ้อนกันจนไม่มีช่องทาง แอปจะแจ้งให้จัดตำแหน่งใหม่แทนการวาดเส้นผ่านเนื้อตาราง

`localStorage` ผูกกับเบราว์เซอร์ โปรไฟล์ และ URL/พอร์ต ข้อมูลอาจหายหากล้างข้อมูลเว็บไซต์หรือใช้โหมดส่วนตัว จึงควรดาวน์โหลด JSON เพื่อสำรองงาน ไม่ได้เขียนไฟล์ลงดิสก์โดยอัตโนมัติ

## Business Flowchart ที่อ้างอิง ER

1. สร้าง/นำเข้าตาราง ER ก่อน แล้วคลิกแท็บ **Flowchart** ด้านบน
2. กด **สร้างขั้นตอนจากตาราง ER** เลือกตารางที่เกี่ยวข้อง ระบบสร้างกล่องขั้นตอนที่ผูกกับชื่อตาราง แต่ยังไม่เชื่อมลำดับธุรกิจเอง
3. เพิ่ม **เริ่มต้น / ขั้นตอน / เงื่อนไข / สิ้นสุด** จากแผงซ้าย
4. คลิกกล่องเพื่อแก้ชื่อ รายละเอียด ตาราง และคอลัมน์อ้างอิง หากคอลัมน์ใช้ Enum จะเห็นค่าที่มีใน ER เช่นสถานะของ deal เพื่อประกอบการเขียนเงื่อนไข
5. ลากจุดด้านล่างไปยังจุดด้านบนของขั้นตอนถัดไป สำหรับเงื่อนไข ใช้จุด **ใช่** ด้านขวาหรือ **ไม่ใช่** ด้านซ้าย แต่ละแขนงเชื่อมได้หนึ่งปลายทาง
6. คลิกเส้นเพื่อเปลี่ยนข้อความ/เงื่อนไขบนเส้น หรือลบเส้น; คลิกกล่องแล้วกดถังขยะเพื่อลบขั้นตอนและเส้นที่อ้างถึง
7. กด **จัด Flowchart** เพื่อจัดจากบนลงล่างด้วย ELK.js และ **พอดีหน้าจอ** เพื่อดูทั้งหมด
8. กด **บันทึกโปรเจกต์** เพื่อเก็บ ER และ Flowchart ใน `.erd.json` เดียวกัน เปิดกลับได้และกู้คืนหลังรีเฟรชได้

ตัวอย่างที่ผู้ใช้กำหนดได้: เริ่ม → สร้างโพสต์ (`marketplace_posts`) → พูดคุย (`chat_rooms`) → ยืนยันข้อตกลงหรือไม่ (`deals.status`) → ตกลงซื้อขาย (`deals`) → รีวิว (`user_reviews`) → สิ้นสุด โดยแขนง “ไม่ใช่” อาจย้อนกลับไปแก้ข้อมูล ขั้นตอนและเงื่อนไขนี้เป็นสิ่งที่ผู้ใช้กำหนด ไม่ได้อนุมานจาก Foreign key

เมื่อเปลี่ยนชื่อตารางผ่าน Visual Designer ลิงก์ของ Flowchart จะเปลี่ยนตาม แต่ชื่อขั้นตอนที่คุณเขียนเองยังคงเดิม หากลบตาราง/คอลัมน์ หรือเปลี่ยนชื่อผ่านโค้ดจนหาชื่อเดิมไม่พบ แอปจะแจ้งบนกล่องและให้เลือกข้อมูลอ้างอิงใหม่ โดยไม่ลบขั้นตอนหรือเงื่อนไขของคุณ ปุ่ม **เปิดตารางนี้ใน ER** ใช้กลับไปดูตารางต้นทางได้

ไฟล์ JSON เก่าที่ยังไม่มี `workflow` เปิดได้โดย Flowchart เริ่มว่าง การเปิดไฟล์ DBML เป็นการเปิดโปรเจกต์โครงสร้างใหม่และไม่บรรจุ Flowchart เดิม ให้บันทึก `.erd.json` ก่อนสลับโปรเจกต์

## เปิดไฟล์โครงสร้างที่ส่งมา

ไฟล์ตัวอย่างจริงอยู่ที่ `examples/durian-marketplace.dbml` (เนื้อหาเดิมจากไฟล์ที่ส่งมา) กด **เปิดไฟล์** แล้วเลือกไฟล์นี้ หรือวางข้อความเดิมทั้งหมดใน Code Editor จะได้ **15 ตาราง, 27 ความสัมพันธ์, 12 Enum และ 5 composite indexes**

รุ่นก่อนหน้าจะหยุดที่ `[pk, increment]` แล้วคง Diagram ร้านค้าตัวอย่างไว้ รุ่นนี้รองรับ `increment`, inline `ref`, `indexes`, `Enum`, quoted references และ optional operators เช่น `?<?` แล้ว และจะแสดงแถบเตือนบน Diagram เมื่อโค้ดมีข้อผิดพลาด จึงแยกได้ว่าภาพนั้นมาจากข้อมูลเก่า

เมื่อวางหรือนำเข้าตารางชุดใหม่ แอปจะจัดตำแหน่งด้วย ELK.js และปรับมุมมองให้อัตโนมัติ สามารถคลิกชื่อตารางใน Visual Designer เพื่อซูมดูทีละตารางได้

บรรทัดสุดท้ายของไฟล์เป็น self-reference จาก `role_verification_requests.license_number` ไปยัง `role_verification_requests.id` แบบ optional ทั้งสองด้าน แอปเก็บเส้นนี้ตามต้นฉบับ แต่ไม่ได้ตรวจความเข้ากันของชนิดข้อมูล (`varchar` กับ `int`) หากไม่ต้องการความสัมพันธ์นี้ให้ลบบรรทัด Ref สุดท้าย

## ไวยากรณ์ที่รองรับ (DBML subset)

ใช้หนึ่งคำสั่งต่อบรรทัด เปิดและปิดตารางคนละบรรทัด ชื่อตาราง/คอลัมน์ใช้ตัวอักษรอังกฤษ ตัวเลข และ `_` โดยห้ามขึ้นต้นด้วยตัวเลข ชื่อแยกตัวพิมพ์เล็ก/ใหญ่

```dbml
// คอมเมนต์แบบบรรทัด
Table users {
  id uuid [pk]
  email varchar(255) [unique, not null]
  created_at timestamp
}

Table posts {
  id uuid [pk]
  user_id uuid [not null]
  title varchar(200)
  price decimal(10,2)
}

Ref: posts.user_id > users.id
```

ชนิดข้อมูลเป็นชื่อ เช่น `uuid`, `integer`, `text`, `timestamp`, `RoleType` หรือชื่อพร้อมตัวเลขในวงเล็บ เช่น `varchar(255)`, `decimal(10,2)` รองรับ flags `pk`/`primary key`, `unique`, `not null`, `null`, `increment` และ inline references เช่น `user_id int [not null, ref: > users.id]`

รองรับ `Enum` ที่มีค่าหนึ่งค่าต่อบรรทัด (ชื่อ หรือข้อความใน double quotes) และ `indexes` แบบ single/composite columns พร้อม flags `unique` หรือ `pk` ข้อมูล Enum/indexes เก็บไว้ในโปรเจกต์และโค้ด แต่ไม่ได้สร้างเป็นกล่องตารางหรือเส้นเพิ่มใน Diagram

```dbml
Enum RoleType {
  SELLER
  BUYER
}

Table user_roles {
  id int [pk, increment]
  user_id int [not null, ref: > users.id]
  role_type RoleType

  indexes {
    (user_id, role_type) [unique]
  }
}
```

การบันทึกจาก Visual Designer จะคง `increment`, `Enum`, `indexes` และ optional relationships ไว้ โดยแปลง inline ref เป็น `Ref:` ที่ท้ายโค้ด ส่วนการแก้ไข Enum/indexes/increment ให้ใช้ Code Editor ถ้าลบหรือเปลี่ยนชื่อคอลัมน์ที่อยู่ใน index ต้องแก้ index ที่อ้างถึงด้วย

| รูปแบบ | ความหมาย |
| --- | --- |
| `Ref: posts.user_id > users.id` | หลายต่อหนึ่ง (N : 1) |
| `Ref: users.id < posts.user_id` | หนึ่งต่อหลาย (แปลงภายในเป็น N : 1) |
| `Ref: profiles.user_id - users.id` | หนึ่งต่อหนึ่ง (1 : 1) |
| `Ref: authors.id <> books.id` | หลายต่อหลาย (N : N) |
| `Ref: posts.user_id >? users.id` | N : 0..1 |
| `Ref: "users"."id" ?<? "posts"."user_id"` | optional ทั้งสองฝั่ง แปลงเป็น 0..N : 0..1 ภายใน |

ยังไม่รองรับ DBML เต็มรูปแบบ เช่น ชื่อที่มีช่องว่าง, schema namespace, Note, default, expression/named indexes, composite foreign keys, Ref แบบ block และ TablePartial รองรับ double quotes ใน `Ref` สำหรับชื่ออังกฤษ/ตัวเลข/underscore เท่านั้น

เส้นความสัมพันธ์เป็น metadata สำหรับ Diagram ไม่ได้สร้างหรือแก้ไขฐานข้อมูลจริง ยังไม่ตรวจชนิดข้อมูลของ Foreign key, ความเป็น unique ของปลายทาง หรือบังคับ cardinality ให้ถูกต้องตามกฎ SQL หากเปลี่ยนชื่อคอลัมน์ใน Visual ความสัมพันธ์ที่อ้างชื่อเดิมจะถูกลบและต้องเชื่อมใหม่ ส่วนการเปลี่ยนชื่อตารางจะอัปเดตความสัมพันธ์ให้

## การทำงานภายใน

โค้ดใน Editor ถูกแปลงด้วย `parseSchema()` เป็น `Schema` กลาง ซึ่งประกอบด้วย tables/columns/relations จากนั้น App แปลงเป็น nodes/edges ของ React Flow ส่วนการแก้ไขใน Visual จะตรวจสอบ `Schema` แล้วแปลงกลับด้วย `serializeSchema()` ตำแหน่งตารางเก็บแยกจากโครงสร้าง จึงสลับโหมดได้โดยไม่สูญเสียตำแหน่ง

แอปใช้รูปแบบจัดตำแหน่งที่เลือกเมื่อกดเมนู หรือเมื่อวาง/นำเข้าตารางที่ยังไม่มีตำแหน่ง โดยรอให้หยุดพิมพ์ 450 ms ก่อนเริ่ม ระหว่างลากใช้ live positions แยกจากเอกสารที่บันทึก และแสดงเส้น preview; หลังปล่อยจึงบันทึกและให้ worker หาเส้นทางละเอียด มีหนึ่งงานที่กำลังทำและเก็บคำขอค้างเฉพาะตำแหน่งล่าสุด พร้อมป้องกันผลเก่าทับข้อมูลใหม่ ถ้า Worker ใช้ไม่ได้จะคำนวณแบบ fallback หลังปล่อย ส่วน Flowchart มี React Flow provider/state ของตนเองและเก็บ workflow แยกจาก schema

## ทดสอบและ build

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

`build` ตรวจ TypeScript แล้วสร้างไฟล์ใน `dist/` ส่วน `preview` เปิดผล build เช่น http://127.0.0.1:4173 ให้ใช้ผ่าน HTTP server ไม่ควรดับเบิลคลิก `dist/index.html` โดยตรง คำสั่ง dev/preview รับการเชื่อมต่อเฉพาะเครื่องนี้ (`127.0.0.1`)

ทดสอบด้วยตัวเอง: เพิ่มตารางสองตาราง เชื่อม Foreign key แก้โค้ดให้ผิดเพื่อดู error แก้ให้ถูก สลับโหมด จัดตำแหน่ง ดาวน์โหลด JSON แล้วเปิดกลับ และรีเฟรชเพื่อตรวจการบันทึก

ELK.js เป็น layout engine ขนาดใหญ่ จึงแยกโหลดเมื่อกดจัดตำแหน่งครั้งแรก Vite อาจแจ้งเตือน chunk ใหญ่กว่า 500 kB ระหว่าง build ซึ่งไม่ทำให้ build ล้มเหลว

## การนำขึ้น Netlify (Deploy to Netlify)

โปรเจกต์นี้เป็น Client-side Web Application ล้วน สามารถนำขึ้นโฮสต์บน Netlify ได้ทันที โดยมีไฟล์คอนฟิก [netlify.toml](netlify.toml) กำหนดค่า build command และ SPA rewrite ไว้แล้ว

เลือกทำได้ 3 วิธี:

1. **Netlify Drop (สะดวกที่สุด — ไม่ต้องใช้ Git หรือ CLI):**
   - รัน `npm.cmd run build` เพื่อสร้างโฟลเดอร์ `dist`
   - เปิดเบราว์เซอร์ไปที่ [app.netlify.com/drop](https://app.netlify.com/drop)
   - ลากโฟลเดอร์ `dist` ทั้งโฟลเดอร์ไปวางบนหน้าเว็บ Netlify จะ deploy ให้ทันทีพร้อมแจก URL เข้าใช้งาน
2. **เชื่อมต่อผ่าน Git (GitHub / GitLab):**
   - Push โปรเจกต์ขึ้น Repository บน GitHub
   - ในหน้า Netlify Dashboard เลือก **Add new site > Import an existing project**
   - Netlify จะอ่านการตั้งค่าจาก `netlify.toml` โดยอัตโนมัติ (Build command: `npm run build`, Publish directory: `dist`)
3. **Netlify CLI:**
   - รัน `npx netlify-cli deploy --prod --dir=dist` ใน PowerShell เพื่อล็อกอินและ deploy จาก Terminal

> [!NOTE]
> แอปพลิเคชันบันทึกข้อมูล Diagram และ Flowchart ใน `localStorage` ของแต่ละโดเมน หากเข้าใช้งานผ่าน URL ของ Netlify ข้อมูลจะถูกเก็บในเบราว์เซอร์แยกจากตอนรันบน localhost แนะนำให้ดาวน์โหลดไฟล์ `.erd.json` เพื่อนำไปเปิดใช้งานบนโดเมนใหม่
